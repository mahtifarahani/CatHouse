# Webviews

Status: **pages built in Phases 1–3** (Setup, Orchestrator, Overview, Runs, Repos, Profiles, Models, Diagnostics).

## One Activity Bar surface

The complete application is one `WebviewView` in the `cathouse` Activity Bar container (`cathouse.sidebar`, `packages/extension/src/panel/sidebar.ts`). There is no intermediary status-only sidebar, Open Dashboard button, or separate editor `WebviewPanel`.

It loads the Vite build directly. `retainContextWhenHidden` is off; safety-critical draft state goes in `viewState` (see `protocol.md`).

## Loading and CSP (`packages/extension/src/panel/webview-html.ts`, `host.ts`)

- The Vite build writes fixed names, `packages/extension/dist/webview/index.js` and `index.css` (no hashes; `packages/webview/vite.config.ts`), so the host can reference them.
- `localResourceRoots` = `dist/webview` only.
- CSP: `default-src 'none'; img-src <cspSource> data:; style-src <cspSource>; font-src <cspSource>; script-src 'nonce-<random>'`. No `unsafe-inline`, no `unsafe-eval` (unit-tested). React's style props go through the CSSOM, which the CSP does not block. Never inject `<style>` tags or inline `style=""` HTML strings.
- A new 16-byte base64 nonce is made for every HTML load.

## Styling (`packages/ui`)

- Tailwind v4 via `@tailwindcss/vite`. `packages/webview/src/index.css` imports `tailwindcss`, then `@cathouse/ui/theme.css`, and adds `@source "../../ui/src"` so component classes are generated.
- `theme.css` maps every colour token to a `--vscode-*` variable (`bg-primary` = `--vscode-button-background`, `text-muted-foreground` = `--vscode-descriptionForeground`, `text-danger` = `--vscode-errorForeground`, …), so Light, Dark and High Contrast work with no theme-specific CSS. **Never use literal colours.**
- Focus ring: `--vscode-focusBorder`. Reduced motion is honoured globally.
- Dense supporting text uses a 13 px minimum (`--text-xs`) with a 20 px line height, the base layer uses 1.45 line height, and shared inputs have a 32 px minimum height. This keeps the Activity Bar UI readable without changing the user's VS Code base-font setting.
- Components follow shadcn conventions (`cva` variants + `cn()`). Today: `Button` (primary/secondary/ghost). Add shadcn components by copying them into `packages/ui/src/components/` and replacing their colour tokens with the ones above.

## Strings

`packages/webview/src/lib/strings.ts` holds every user-facing string, used through `t(key, vars)` (ADR 0004). The manifest uses `packages/extension/package.nls.json`; host-side strings will use `vscode.l10n.t` with `packages/extension/l10n/`. When a second locale arrives, switch `strings.ts` to `@vscode/l10n` bundles without touching call sites. Use logical CSS properties so RTL works.

When the status bar reports `setup needs attention` (`canStart === false`), the Setup tab carries a theme-aware red dot and exposes the same warning in its accessible name; the signal is therefore not colour-only.

### Transcript Markdown

User and assistant text events render through `session/MarkdownText.tsx`, backed by `react-markdown` and `remark-gfm`. The renderer supports headings, paragraphs, emphasis, links, blockquotes, ordered and unordered lists, inline and fenced code, rules, tables, task lists and strikethrough. Elements use VS Code theme tokens and scroll horizontally where code or tables are wider than the view. Raw HTML is skipped rather than inserted into the DOM, and links use the renderer's safe URL transform plus `rel="noreferrer"`; never replace this path with `dangerouslySetInnerHTML`.

### Transcript layout

`session/Transcript.tsx` renders the folded transcript (`toTranscript` in `useSession.ts`) as a chat rather than a log:

- User messages sit under a `You` header in a full-width, bordered card that starts at the same left edge as orchestrator output (right-aligned bubbles were dropped: in a wide view multi-line messages started mid-screen). Orchestrator output is indented under a `catherd` header that appears once per assistant stretch.
- Consecutive tool calls at the same depth are grouped into one **steps card** (`session/blocks.ts`, `toBlocks`, unit-tested). Each step shows a status icon (spinner / check / cross), a tool-type icon, the bare tool name, an MCP server chip (for example `catherd`), a one-line summary and the live elapsed time. Expanding a step shows its input as a key/value list and its output (truncated to 4000 characters, red when `isError`). Groups longer than five steps show the last four with a "Show N earlier steps" button.
- `init` is a centered status pill, `run_started` a highlighted run card, sub-agent `task` events a card with a status badge, and turn results / compaction are labelled dividers. An `inbound` event (a turn catherd started by pushing a finished role into the session, catherd 1.1+) is a "catherd reported back" divider with the cat icon; the notice text itself is not available from the SDK.
- Icons come from `Icon` in `packages/ui/src/components/icons.tsx`: inline stroke SVGs with Lucide geometry, sized at `1em` and coloured by `currentColor`, so they follow the text-size setting and every theme. No icon font or extra dependency is loaded (CSP stays unchanged).

### Settings (text size)

A gear button sits at the far right of the status bar, next to the catherd version (`lib/settings.tsx`, `SettingsMenu`). It opens a small popover (Escape or an outside click closes it) with a **Text size** control: A−/A+ buttons, a slider from 80 % to 160 % in 5 % steps and 90/100/115/130 % presets. These controls edit a draft shown in a fixed-height preview line; the view rescales only when **Apply** (or Enter on the slider) is pressed. Applying live while dragging reflowed the whole view and moved the popover and slider out from under the pointer. Cancel, Escape or an outside click discard the draft.

The value is written to the `--cathouse-font-scale` custom property on `<html>`. `packages/ui/src/theme.css` defines `--text-base` as `var(--vscode-font-size) * scale`, and `html` uses `--text-base`, so body text, rem-based spacing and `text-xs` all scale together while still following the user's VS Code font size. The scale is a presentation preference only: it is stored in the webview's `vscode.getState()` plus `localStorage` (key `cathouse.fontScale`), applied before the first render in `main.tsx`, and never touches catherd files. `clampScale` is unit-tested. CSP needs no `unsafe-inline` because the property is set through the CSSOM.

Remaining work: the new transcript and settings popover were verified by lint, typecheck, unit tests, a production build and a check that the compiled CSS contains the new utilities; an owner pass in the real Extension Development Host (Light, Dark, High Contrast, narrow sidebar) is still to do.

Profile hydration runs only when a new server document arrives; draft edits must never be a dependency of that effect or clean-state resets can overwrite user input. `usePoll` queues one rerun when a key change or explicit refresh occurs during an in-flight request, so New/Delete/profile switching cannot lose the load for the newly selected profile.

Phase 5 adds one non-wrapping dashboard status bar below the native `CatHouse` title. It contains the repository name without a `Repository:` prefix (a picker in multi-root workspaces), setup mood, current profile, dirty count and catherd version; if the Activity Bar becomes narrower than its contents, the bar scrolls horizontally instead of wrapping. The dashboard also has an ARIA tablist with arrow/Home/End navigation, focus-trapped dialogs with Escape, an accessible toast live region, and non-colour symbols for model rung state. Webview asset URLs carry a per-attach cache key so a reloaded Extension Development Host cannot retain an old fixed-name Vite bundle.
