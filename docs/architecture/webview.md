# Webviews

Status: **UI rebuilt on 2026-10-02** into five tabs: Chat, Runs, Profile, Models, Setup. Overview was folded into Runs, Repos into the Chat repo menu, and Diagnostics into Setup.

Profile now begins with a CatHouse-level orchestrator selector (Claude Code or Codex). It applies immediately to new chats, disables during an active session, and asks Setup to recheck the selected host. If Setup's gate closes because the new host needs installation, Profile and Setup remain reachable so the user can switch back or finish Setup. The selector is global CatHouse state, not a catherd profile patch. Details: ADR 0009.

Chat offers the same change at the point of a Claude session-limit response. The transcript identifies that specific assistant message, renders one **Switch to Codex** action beside the latest matching message, and explains that the current Claude chat ends and stays with Claude. The action calls `session.stop` for an active chat, then `app.setHost(codex)`; the existing Profile/Setup gate handles unmet Codex prerequisites. Other errors and Codex-hosted chats do not show the action. The message and action are translated in all six UI languages.

## One Activity Bar surface

The complete application is one `WebviewView` in the `cathouse` Activity Bar container (`cathouse.sidebar`, `packages/extension/src/panel/sidebar.ts`). There is no intermediary status-only sidebar, Open Dashboard button, or separate editor `WebviewPanel`.

It loads the Vite build directly. `retainContextWhenHidden` is off; safety-critical draft state goes in `viewState` (see `protocol.md`).

## Loading and CSP (`packages/extension/src/panel/webview-html.ts`, `host.ts`)

- The Vite build writes fixed names, `packages/extension/dist/webview/index.js` and `index.css` (no hashes; `packages/webview/vite.config.ts`), so the host can reference them.
- `localResourceRoots` = `dist/webview` only.
- CSP: `default-src 'none'; img-src <cspSource> data:; style-src <cspSource>; font-src <cspSource>; script-src 'nonce-<random>'`. No `unsafe-inline`, no `unsafe-eval` (unit-tested). React's style props go through the CSSOM, which the CSP does not block. Never inject `<style>` tags or inline `style=""` HTML strings.
- A new 16-byte base64 nonce is made for every HTML load.

## Styling (`packages/ui`)

- Tailwind v4 via `@tailwindcss/vite`. `packages/webview/src/index.css` imports `tailwindcss`, then `@cathouse/ui/theme.css`, and adds `@source "../../ui/src"` so component classes are generated.
- `theme.css` maps every colour token to a `--vscode-*` variable (`bg-primary` = `--vscode-button-background`, `text-muted-foreground` = `--vscode-descriptionForeground`, `text-danger` = `--vscode-errorForeground`, …), so Light, Dark and High Contrast work with no theme-specific CSS. **Never use literal colours.**
- Focus ring: `--vscode-focusBorder`. Reduced motion is honoured globally.
- The webview's base CSS gives enabled buttons, links, selects, tabs, menu items, switches, radio controls and associated labels a pointer cursor. VS Code's webview reset does not provide this consistently; disabled controls keep their noninteractive cursor.
- `html`, `body` and `#root` occupy the webview height without their own scrolling; the active tab panel owns page scrolling. Setup's install output wraps within its row and grows with the page, so the page and output do not show two vertical scrollbars. VS Code body padding is reset to zero. Keep long output in normal flow when editing Setup.
- The Chat composer keeps the same neutral outer border while typing. It does not use a focused border colour. VS Code injects textarea focus styling into webviews, so a scoped rule in `packages/webview/src/index.css` suppresses the textarea's focused outline and shadow as well. The caret still shows text entry focus.
- The composer permission mode shows the selected label with a chevron directly after it. A transparent native select covers that compact trigger, preserving native keyboard and screen-reader behaviour; the trigger draws the focus outline.
- Dense supporting text uses a 13 px minimum (`--text-xs`) with a 20 px line height, the base layer uses 1.45 line height, and shared inputs have a 32 px minimum height. This keeps the Activity Bar UI readable without changing the user's VS Code base-font setting.
- **Borders only on inputs and focus rings.** Groups use spacing, rounded corners and two soft fills from `theme.css`: `bg-surface` (5 % of the foreground colour) and `bg-surface-hover` (9 %). `bg-accent-soft` (18 % of the button colour) marks the user's chat bubble and prompt cards. `Section`, `Collapsible`, `Card`, `Badge`, `Meter` and `ErrorText` in `packages/ui/src/components/bits.tsx` follow this rule, so new pages inherit it.
- **Responsive by container, not viewport.** `<main>` is a Tailwind `@container`, and labels collapse at container widths: tabs become icon-only below `@[30rem]`, and secondary labels (Re-check, Continue in chat, Run in terminal) below about `@[20–22rem]`. `rem` here follows the VS Code font (13 px by default), so `30rem` ≈ 390 px. Every row uses `min-w-0` + `truncate` or wraps; nothing scrolls sideways. Checked at 240, 300 and 600 px.
- Components follow shadcn conventions (`cva` variants + `cn()`). `Button` has variants primary/secondary/ghost/quiet and sizes md/sm/icon/iconSm. `controls.tsx` adds `IconButton` (its label is both its `aria-label` and tooltip), `Menu`/`MenuItem`/`MenuSeparator` (a popover that opens up or down, closes on Escape or an outside click, and moves with the arrow keys), `Switch` (a checkbox with `role="switch"`) and `Segmented` (a radiogroup). Icons are added to `icons.tsx` as Lucide path data.

## Strings

`packages/webview/src/lib/strings.ts` holds every user-facing string, used through `t(key, vars)` (ADR 0004). The manifest uses `packages/extension/package.nls.json`; host-side strings will use `vscode.l10n.t` with `packages/extension/l10n/`. When a second locale arrives, switch `strings.ts` to `@vscode/l10n` bundles without touching call sites. Use logical CSS properties so RTL works.

## Pages (`packages/webview/src/pages/`, `session/`, `setup/`)

Navigation (`App.tsx`): **Chat · Runs · Profile · Models · Setup**, each an icon tab with a label when there is room, plus the settings gear at the end of the strip. **Chat is the default on every fresh webview load.** **Only Setup is shown until `gateOpen`** (docs/architecture/setup.md); the strip then shows just the CatHouse title and the gear. When `canStart === false` the Setup tab carries a red dot and its accessible name says "setup needs attention". There is no status bar: the repo and profile live in the Chat context row, the catherd version in Setup.

Design rule behind the rebuild: **one action, one place.** A control shows only when it can act (no permanently disabled Interrupt/Stop), a choice applies in one step (no select-then-press-Activate), and an undo replaces confirm dialogs where catherd allows it.

### Transcript Markdown

User and assistant text events render through `session/MarkdownText.tsx`, backed by `react-markdown` and `remark-gfm`. The renderer supports headings, paragraphs, emphasis, links, blockquotes, ordered and unordered lists, inline and fenced code, rules, tables, task lists and strikethrough. Elements use VS Code theme tokens and scroll horizontally where code or tables are wider than the view. Raw HTML is skipped rather than inserted into the DOM, and links use the renderer's safe URL transform plus `rel="noreferrer"`; never replace this path with `dangerouslySetInnerHTML`.

### Transcript layout

`session/Transcript.tsx` renders the folded transcript (`toTranscript` in `useSession.ts`) as a chat:

- **User messages are right-aligned bubbles** (max 85 % wide, `bg-accent-soft`, a small corner on the speaker side). **catherd's output is left-aligned** under a header with a filled cat avatar in the button colour, the name `catherd` and "orchestrator · <model>", so the two sides differ in place, shape and colour.
- **Which model and role is working.** The orchestrator's model comes from the SDK init message (`SessionEvent.init.model`, mapped in `packages/extension/src/orchestrator/events.ts`). Sub-agent task cards parse catherd's native agent names (`catherd-<profile>-<role>-<model>-<effort>`) and show the role and model. Worker roles that catherd runs outside the session (Codex, opencode, …) show in the live roles strip above the input: catherd names live dispatches `<role>-<lane>` (catherd `src/services/summary.ts` has no role field on live rows), with the matching finished record as a fallback.
- Consecutive tool calls at the same depth are grouped into one tinted **steps card** (`session/blocks.ts`, `toBlocks`, unit-tested). Each step shows a status icon, a tool-type icon, the bare tool name, an MCP server chip, a one-line summary and the live elapsed time; expanding shows input as key/value pairs and output (truncated to 4000 characters, red when `isError`). Groups longer than five steps show the last four with "Show N earlier steps".
- `init` is a centered pill, `run_started` a tinted run card, turn results / compaction are labelled dividers, and `inbound` (catherd 1.1+ pushed a finished role into the session) is a "catherd reported back" divider. While a turn is active a "catherd is working…" line sits under the last message.
- Icons come from `Icon` in `packages/ui/src/components/icons.tsx`: inline stroke SVGs with Lucide geometry, sized at `1em` and coloured by `currentColor`. No icon font or extra dependency (CSP unchanged).

### Settings (text size)

A gear button sits at the end of the tab strip (`lib/settings.tsx`, `SettingsMenu`). It opens a small popover (Escape or an outside click closes it) with a **Text size** control: A−/A+ buttons, a slider from 80 % to 160 % in 5 % steps and 90/100/115/130 % presets. These controls edit a draft shown in a fixed-height preview line; the view rescales only when **Apply** (or Enter on the slider) is pressed. Applying live while dragging reflowed the whole view and moved the popover and slider out from under the pointer. Cancel, Escape or an outside click discard the draft.

The value is written to the `--cathouse-font-scale` custom property on `<html>`. `packages/ui/src/theme.css` defines `--text-base` as `var(--vscode-font-size) * scale`, and `html` uses `--text-base`, so body text, rem-based spacing and `text-xs` all scale together while still following the user's VS Code font size. The scale is a presentation preference only: it is stored in the webview's `vscode.getState()` plus `localStorage` (key `cathouse.fontScale`), applied before the first render in `main.tsx`, and never touches catherd files. `clampScale` is unit-tested. CSP needs no `unsafe-inline` because the property is set through the CSSOM.

Profile hydration runs only when a new server document arrives and nothing is waiting to be saved; draft edits must never be a dependency of that effect or a refresh can overwrite user input. `usePoll` queues one rerun when a key change or explicit refresh occurs during an in-flight request, so New/Delete/profile switching cannot lose the load for the newly selected profile.

Accessibility: an ARIA tablist with arrow/Home/End navigation (icon-only tabs keep their name in `aria-label` and `title`), menus with `role="menu"` and arrow keys, switches with `role="switch"`, segmented controls as radiogroups, state never shown by colour alone (status icons + screen-reader text), and a polite toast live region. Webview asset URLs carry a per-attach cache key so a reloaded Extension Development Host cannot retain an old fixed-name Vite bundle.
